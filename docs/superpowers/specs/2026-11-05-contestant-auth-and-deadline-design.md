# การออกแบบระบบบัญชีผู้สมัคร (Email + Password) การจัดการผลงานสูงสุด 2 โครงการ และการตั้งวันปิดรับสมัครแบบยืดหยุ่น

**วันที่:** 5 พฤศจิกายน 2569  
**โครงการ:** KMUTNB Innovation Awards 2027 (`innoaward`)

---

## 1. เป้าหมายและเหตุผล (Intent & Why)
เพื่อให้ผู้สมัครสามารถใช้ **อีเมลและรหัสผ่าน (Email + Password)** ล็อกอินกลับเข้ามาในระบบได้อย่างปลอดภัยจากทุกอุปกรณ์ เพื่อดูสถานะการคัดเลือกทั้ง 3 รอบ แก้ไขข้อมูลใบสมัครหรือแบบร่างที่บันทึกไว้ และอัปเดตลิงก์เอกสารประกอบ (เช่น โปสเตอร์และสไลด์นำเสนอ) ได้ตามช่วงเวลาที่กำหนด พร้อมทั้งให้ผู้จัดงานสามารถปรับหรือเลื่อนวันปิดรับสมัครได้เองจากจุดเดียว

---

## 2. ขอบเขตเป้าหมาย (Goals, Non-Goals & Anti-Goals)
- **Goals (สิ่งที่ต้องทำ):**
  - ล็อกอินและลงทะเบียนด้วย **Email + Password** จริง (ตรวจสอบรหัสผ่านจริง และแสดงข้อความแจ้งเตือนชัดเจนเมื่ออีเมลไม่ถูกต้องหรือรหัสผ่านผิด)
  - จำกัดสิทธิ์ **1 บัญชีส่งได้สูงสุดไม่เกิน 2 โครงการ** (นับรวมทั้งสถานะแบบร่าง `DRAFT` และส่งแล้ว `SUBMITTED`)
  - มีหน้ารวม **“ผลงานของฉัน (สูงสุด 2 โครงการ)”** ในหน้าต่าง Portal เมื่อล็อกอินแล้ว เพื่อดูสถานะ 3 รอบ เลือกกลับมาแก้ไขฟอร์มทั้ง 3 ขั้นตอน หรือกดสร้างโครงการที่ 2
  - อนุญาตให้เจ้าของบัญชีแก้ไขฟอร์มทั้ง 3 ขั้นตอนได้แม้กดส่ง (`SUBMITTED`) ไปแล้ว **จนถึงวันปิดรับสมัครที่กำหนด (`submissionDeadline`)**
  - หลังพ้นวันปิดรับสมัคร ระบบล็อกข้อมูลหลักของใบสมัครอัตโนมัติ แต่ยังเปิดให้เจ้าของบัญชีล็อกอินเข้ามา **แนบ/อัปเดตลิงก์โปสเตอร์ (PDF) และสไลด์นำเสนอ** สำหรับรอบที่ 2 / รอบชิงชนะเลิศได้
  - ปรับหน้าค้นหาด้วย `Tracking Code` สาธารณะให้เป็น **ดูสถานะอย่างเดียว (View-Only, ปิดบังข้อมูลส่วนบุคคลตาม PDPA)** และต้องเข้าสู่ระบบก่อนจึงจะแก้ไขข้อมูลหรือแนบไฟล์ได้
  - รองรับการกำหนดและเลื่อน **วันปิดรับสมัคร (`submissionDeadline`)** ได้เองผ่านฐานข้อมูล (`CompetitionYear.submissionEnd`) และ API (`PATCH /api/config/deadline`) พร้อมค่าตั้งต้นสำรองใน Config/Env
- **Non-Goals (สิ่งที่อยู่นอกขอบเขตรอบนี้):**
  - ระบบส่งอีเมลรีเซ็ตรหัสผ่านอัตโนมัติผ่าน SMTP ภายนอก หรือ OAuth (Google/LINE Login)
- **Anti-Goals (สิ่งที่ต้องหลีกเลี่ยง):**
  - ห้ามยอมให้ล็อกอินผ่านเมื่อกรอกรหัสผ่านผิด (ต้องนำโหมดจำลองที่สร้างบัญชีปลอมอัตโนมัติตอนล็อกอินออก)
  - ห้ามให้ผู้ที่ไม่ได้ล็อกอินเป็นเจ้าของโครงการแก้ไขลิงก์ไฟล์ผ่านหน้าค้นหา `Tracking Code` สาธารณะ

## 3. ข้อจำกัดของระบบ (Constraints)
- ต้องทำงานร่วมกับโครงสร้างฐานข้อมูล Prisma เดิม (`User`, `Submission`, `TeamMember`, `CompetitionYear`) โดยไม่กระทบข้อมูลผลงานเดิม
- หน้าบ้าน (`client/src/App.jsx`) ต้องรองรับกรณีที่เปิดใช้งานแบบ Offline Fallback (ใช้ข้อมูลใน `localStorage` สำรองเมื่อไม่ได้เชื่อมต่อ API หลังบ้าน)

---

## 4. ทางเลือกที่พิจารณา (Approaches)

### แนวทางที่ 1 (เลือกใช้): แท็บ “ผลงานของฉัน” ในหน้าต่าง Portal เดิม + ตั้งวันปิดรับสมัครผ่านฐานข้อมูล/API (พร้อมค่า Fallback)
- เพิ่มมุมมองรายการผลงานของผู้สมัคร (1–2 โครงการ) ในหน้าต่าง Portal เดิม เมื่อคลิกเลือกโครงการจะโหลดข้อมูลจากฐานข้อมูลเข้าสู่ฟอร์ม 3 ขั้นตอนเพื่อแก้ไขหรืออัปเดตไฟล์ และซิงก์วันปิดรับสมัครจาก `GET /api/config` (`submissionEnd`) ทั้งหน้าบ้านและหลังบ้าน
- **เหตุผลที่เลือก:** กระทบโครงสร้างหน้าเว็บเดิมน้อยที่สุด ผู้สมัครใช้งานต่อเนื่องในหน้าต่างเดียว และเปลี่ยนวันปิดรับสมัครได้จากจุดเดียวโดยไม่ต้องแก้โค้ดหลายที่

### แนวทางที่ 2: แยกหน้า Dashboard ผู้สมัครเป็นหน้าใหม่ (`#/dashboard`) + ตั้งวันปิดรับสมัครผ่านไฟล์ `.env` เท่านั้น
- แยก Route ใหม่สำหรับผู้สมัคร และตั้งวันปิดรับสมัครในไฟล์ `.env`
- **เหตุผลที่ไม่เลือก:** การเลื่อนวันปิดรับสมัครต้องแก้ไฟล์และสั่ง Build/Deploy ใหม่ทุกครั้ง และต้องรื้อระบบ Navigation ของฟอร์มรับสมัครเดิม

## 5. รายละเอียดการทำงานที่ตกลงร่วมกัน (Agreed Design)

### 5.1 ระบบยืนยันตัวตน (Authentication)
- **`POST /api/auth/register`:** สมัครบัญชีผู้เข้าแข่งขันใหม่ด้วยอีเมลและรหัสผ่าน (อย่างน้อย 6 ตัวอักษร) พร้อมคืนค่า JWT Token และข้อมูลผู้ใช้
- **`POST /api/auth/login`:** ตรวจสอบอีเมลและรหัสผ่านกับ `passwordHash` ในตาราง `User` หากไม่พบบัญชีหรือรหัสผ่านไม่ถูกต้อง จะคืนสถานะ `401` พร้อมข้อความแจ้งเตือนภาษาไทยที่ชัดเจน (ตัดการสร้างบัญชีจำลองอัตโนมัติเมื่อรหัสผ่านผิดออก)

### 5.2 การจัดการผลงานสูงสุด 2 โครงการ (`My Projects`)
- เมื่อล็อกอินสำเร็จ ระบบเรียก `GET /api/submissions/my` เพื่อดึงผลงานทั้งหมดของบัญชีนั้น:
  - แสดงการ์ดสรุปผลงานแต่ละชิ้น (ชื่อผลงาน, รหัส `Tracking Code`, สถานะ `DRAFT`/`SUBMITTED`, และสถานะทั้ง 3 รอบ)
  - หากมีผลงานน้อยกว่า 2 โครงการ และยังไม่พ้นวันปิดรับสมัคร จะแสดงปุ่ม **“+ สร้างผลงานใหม่ (โครงการที่ 2/2)”**
  - ฝั่ง Backend (`POST /api/submissions`) ตรวจสอบว่าหากเป็นการสร้างโครงการใหม่ บัญชีนั้นต้องมีผลงานในระบบไม่เกิน 2 โครงการ (หากเกินจะคืน `400 Bad Request` แจ้งว่าส่งครบโควตา 2 โครงการแล้ว)

### 5.3 การแก้ไขใบสมัคร การบันทึกแบบร่าง และการแนบไฟล์ตามช่วงเวลา
- **การบันทึกแบบร่าง (`Save Draft`):** เมื่อล็อกอินแล้วกดบันทึกแบบร่าง ระบบจะส่ง `POST /api/submissions` (`isDraft: true`) ไปบันทึกในฐานข้อมูลผูกกับ `userId` (และสำรองไว้ใน `localStorage`) เพื่อให้ล็อกอินจากเครื่องอื่นแล้วดึงข้อมูลกลับมาทำต่อได้
- **ก่อนพ้นวันปิดรับสมัคร (`now <= submissionDeadline`):**
  - เจ้าของบัญชีสามารถกด **“แก้ไขข้อมูลใบสมัคร / แนบไฟล์”** เพื่อโหลดข้อมูลเดิมกลับเข้าสู่ฟอร์ม 3 ขั้นตอน แก้ไขได้ทุกฟิลด์ (ทั้งโครงการที่เป็น `DRAFT` และ `SUBMITTED`)
- **หลังพ้นวันปิดรับสมัคร (`now > submissionDeadline`):**
  - Backend ปฏิเสธการสร้างใบสมัครใหม่และการแก้ไขข้อมูลหลักของใบสมัคร (`POST /api/submissions` คืน `403` เมื่อเลยกำหนดเวลา)
  - หน้า Portal ของเจ้าของบัญชีจะล็อกการแก้ไขฟอร์ม 3 ขั้นตอน แต่เปิดส่วน **“แนบ/อัปเดตลิงก์โปสเตอร์ (PDF) และสไลด์นำเสนอ”** (`PATCH /api/submissions/tracking/:trackingCode/artifacts`) ให้เจ้าของบัญชีอัปเดตไฟล์ได้
- **หน้าค้นหาด้วย `Tracking Code` สาธารณะ:**
  - แสดงข้อมูลแฟ้มผลงานและสถานะ 3 รอบแบบปิดบังข้อมูลส่วนบุคคล (PDPA Masked) เท่านั้น
  - ซ่อนฟอร์มแก้ไขลิงก์ไฟล์หากผู้ใช้ยังไม่ได้ล็อกอินเป็นเจ้าของผลงาน และแสดงปุ่ม **“เข้าสู่ระบบด้วยอีเมลเพื่อแก้ไขข้อมูล / แนบไฟล์เพิ่มเติม”** แทน

### 5.4 การกำหนดและเลื่อนวันปิดรับสมัคร (`Configurable Deadline`)
- ใช้ฟิลด์ `submissionEnd` ของปีการแข่งขันปัจจุบันในตาราง `CompetitionYear` (และตัวแปรสภาพแวดล้อม `SUBMISSION_DEADLINE` เป็นค่าตั้งต้นสำรอง เช่น `2027-02-28T23:59:59+07:00`)
- `GET /api/config` ส่งค่า `event.submissionDeadline` ให้หน้าบ้านนำไปใช้ตั้งค่า:
  1. นาฬิกานับถอยหลังหน้าแรก (`timeLeft`)
  2. ข้อความแสดงวันปิดรับสมัครและการเปิด/ล็อกปุ่มแก้ไขใบสมัคร
- เพิ่ม Endpoint `PATCH /api/config/deadline` (รองรับสิทธิ์ `ADMIN` หรือรหัสจัดการระบบ) สำหรับเปลี่ยนวันปิดรับสมัครในฐานข้อมูลได้ทันทีเมื่อมีการประกาศขยายเวลารับสมัคร

## 6. รายละเอียดที่ให้ผู้พัฒนาจัดการต่อ (Left to the Builder)
- การจัดวาง UI ของการ์ดรายการผลงาน 1–2 โครงการภายในหน้าต่าง Portal Modal ให้สวยงามและสอดคล้องกับธีมมืด/ทอง/ฟ้าของเว็บไซต์
- ฟังก์ชันแปลงข้อมูล `Submission` + `TeamMember[]` จาก `GET /api/submissions/my` กลับเข้าสู่โครงสร้าง `subForm` ทั้ง 3 ขั้นตอน (`hydrateSubmissionFormFromServer`)
- ชุดทดสอบอัตโนมัติ (Unit & Integration Tests) สำหรับโควตา 2 โครงการ การล็อกอินจริง การตรวจสอบวันปิดรับสมัคร และการป้องกันการแก้ไขไฟล์โดยไม่ล็อกอิน
